# 오늘 한 일

### React + TypeScript 프로젝트 제작 (React, TypeScript, ExpressJS, MongoDB로 만드는 실시간 통신 애플리케이션)

- 호스트 관련 기능 정리
  - 호스트 권한 위임 기능
    - 기능
      - 기존 호스트가 다른 사용자에게 호스트 권한 이전 가능
      - 위임 후 기존 호스트는 일반 멤버 또는 관리자 권한으로 변경
        - 관리자 권한으로 변경되기 위해선 관리자 관련 기능과 관리자 위임 기능도 필요
        - DB에서 그룹 채팅방 내의 role 항목이 필요하고 HOST, ADMIN, MEMBER 같은 구조로 관리 필요
      - 그룹 채팅방에는 시스템 메시지 출력
    - 처리 순서
      - 호스트
      - 위임 대상 선택
      - Socket 이벤트 전송
      - Server
      - 권한 변경
        - HOST / MEMBER
        - MEMBER / HOST
      - DB 저장
      - 모든 사용자에게 변경사항 정보 전달
      - UI 갱신
    - 고려해야 할 사항
      - 자기 자신에게 위임 불가
      - 이미 호스트인 사람에게 위임 불가
      - 그룹원이 1명뿐이면 위임 불가
      - 위임 즉시 권한 UI 변경
  - 호스트 나가기 기능
    - 자동 위임
      - 기능
        - 호스트가 방을 나갈 시에 자동으로 호스트 권한 위임
      - 처리 순서
        - 호스트
        - 나가기
        - 자동으로 호스트 선정
          - ex) 가장 먼저 들어온 사람 등 여러 기준
        - 퇴장
      - 고려해야 할 사항
        - 그룹원이 1명뿐이면 나가기 버튼이 보이지 않고 채팅방 삭제 버튼만 출력
        - 나가는 사용자를 제외한 다른 사용자가 호스트가 되어야 함
        - 원하지 않는 사용자가 호스트가 될 수 있음
    - 직접 선택
      - 기능
        - 호스트가 방을 나갈 시에 위임할 사용자 목록이 표시되고 사용자 선택
      - 처리 순서
        - 호스트
        - 나가기
        - 참여자 목록 표시
        - 호스트 지정
        - 퇴장
      - 고려해야 할 사항
        - 그룹원이 1명뿐이면 나가기 버튼이 보이지 않고 채팅방 삭제 버튼만 출력
        - 호스트 본인은 사용자 목록에 표시되면 안됨
        - 한 번 더 클릭해야 함
  - 그룹 채팅방 특정 멤버 강제 퇴장 기능
    - 기능
      - 호스트가 특정 사용자를 강제로 퇴장
    - 처리 순서
      - 호스트
      - 멤버 클릭
      - 강제 퇴장
      - Socket
      - Server
      - DB 삭제
      - 방 나가기
      - 다른 사용자에게 정보 전달
      - 목록 갱신
    - 고려해야 할 사항
      - 호스트는 호스트 본인 강제 퇴장 불가
      - 관리자는 호스트 강제 퇴장 불가
      - 강제 퇴장된 사용자에게 안내 메시지 출력
  - 추가 기능 고려
    - 관리자 권한 기능
      - 기능
        - 멤버 강제 퇴장
        - 방 정보 수정
          - 공지사항, 제목
        - 초대
      - 불가능 기능
        - 호스트 위임
        - 관리자 지정
        - 관리자 해제
  - 구성 우선 순위
    - 호스트 / 멤버 권한 구조
      - 관리자 기능을 전부 구현하지 않더라도 확장 가능 형태로 미리 추가하는 방향 고려
    - 호스트 권한 위임
    - 호스트 나가기 (직접 위임 후 퇴장)
    - 멤버 강제 퇴장
    - 관리자 권한 추가
    - 관리자 임명/해제
    - 관리자 멤버 강제 퇴장 기능
    - 관리자는 호스트 위임 불가

# 오늘 느낀 점

- 밀린 TIL 내용을 정리하고 호스트 관련 기능을 세부적으로 정리했는데, 정리를 하다보니 생각보다 신경써야할 부분도 많고 호스트 위임만이 아닌 관리자 부여와 관련된 내용도 구성을 해야 할 것 같아서 처음 생각한 내용과는 조금 다르게 일이 커진 느낌이 있긴 하지만 그래도 호스트 관련 여러 기능과 관리자 관련 기능을 추가하면 기능적인 부분도 한단계 더 업그레이드되고 나중에 구성하지 않고 기존 구성한 내용을 사용하면 되니 좋을 것으로 생각이 된다. 우선 그룹 채팅방 정보에서 호스트 정보는 그대로 유지한 채로 role 항목을 추가해 호스트, 관리자, 멤버로 나누고 호스트가 다른 사용자에게 호스트 권한을 위임하는 기능부터 우선 구현한 뒤 그 다음 관리자 부여와 관련된 기능을 구현하는 것으로 진행해볼 예정이다.

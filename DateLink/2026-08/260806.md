# 오늘 한 일

## 커밋한 내용

- 그룹 채팅 사용자 목록 역할 정보 불러오기 및 그룹 멤버 메뉴 역할 관련 조건부 추가 및 호스트 권한 위임 관련 내용 추가

## 수정 내용

- 그룹 채팅방 사용자 목록을 불러와 로그인한 사용자와 선택한 사용자 정보를 확인하고 역할 정보를 하위 컴포넌트로 전달
- 호스트 권한 위임 관련 함수를 구성해 하위 컴포넌트로 전달
- 호스트 권한 위임 관련 액션 함수 추가
- 로그인한 사용자 역할과 선택한 사용자 역할을 조건부로 사용해 문구 또는 버튼 출력
- 타입 에러를 해결하기 위해 타입 정의 수정

## 결과

- 로그인한 사용자 역할과 선택한 사용자 역할을 확인해 그에 맞는 문구 또는 버튼이 출력되는 것을 확인
- 호스트 권한 위임 관련 함수와 Zustand 액션 함수가 연결된 것을 확인
- 수정된 타입 정의로 인해 타입 에러가 발생하지 않는 것을 확인

# 오늘 배운 점

- 역할에 따라 문구와 버튼 출력하는 조건부를 구성하는데 최대한 간결하고 이상한 구조는 피하면서 작성하는게 생각보다 쉽지 않다는 것을 느낌
- 역할에 따라 문구와 버튼이 출력되도록 구성하면서 어떤 기준으로 분류하는 것이 좋은지 다시 한 번 생각해볼 수 있었음 (ex: 권한에 따른 분리 또는 UI 역할에 따른 분리)
- 역할에 따라 문구와 버튼이 출력되는 내용에서 호스트 권한 위임 같은 함수가 직접 사용되도록 하려 했으나, 해당 내용에서는 최대한 UI만 관리하고 상위 컴포넌트에서 모아서 처리하는 방향이 더 좋다는 것을 알게 됨
